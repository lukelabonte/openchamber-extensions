# Project charter

Additions and overrides for this project, layered on top of the shared charter. The captain's orders outrank this file. Hard rules still apply: an override doesn't authorize repository mutation, landing, scope expansion, or discard outside the shared charter's boundaries.

Record project-specific brief requirements, validation, permission-sensitive boundaries, or evidence worth checking here. Keep task progress and decisions in `backlog.md`, durable briefs in `briefs/`, outcomes in `reports/`, and reusable findings in `learnings.md`. Read those records when their task or question is relevant.

Keep the shipping mode in `projects.md`, not a second copy here. Project notes don't broaden a watch's authority or release a handoff hold. `opening.md` remains the captain's editable startup message.
